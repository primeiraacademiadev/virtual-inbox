# Internationalization

The console supports `pt-PT`, `en`, and `fr`. Browser language is used initially, while an explicit selection persists in `localStorage`. English is the fallback. Dates and numbers use the browser's `Intl` API.

The UI dictionary and context are located entirely in `web/src/i18n/`; shared clipboard and search controls consume the context without introducing translation logic into the domain. `src/server.ts` emits stable machine-readable `errorCode` and `errorParams` while retaining the legacy `error` string for compatibility. SSE event types, UUIDs, routes, environment variable names and JSON keys remain invariant.

The localized documentation source is `scripts/i18n-doc-content.json`. `scripts/sync-docs.mjs` creates a `/wiki/{locale}/{document}.md` tree and then `scripts/build-doc-search.mjs` creates one local search index per language. Identical document IDs are used in all three languages, so changing the UI language retains the selected document. No runtime translation service is involved.

## Contributor guidelines

- Add a new UI message to all three maps in `web/src/i18n/catalog.ts`.
- Add new error code translations to `web/src/i18n/errors.ts` without translating their machine identifiers.
- Add each new guide entry to all three language arrays in `scripts/i18n-doc-content.json`.
- Never translate endpoint paths, wire enums, request fields, UUIDs, or executable examples.
- Do not embed secrets in localization catalogues.
- Validate build output and language switching for missing keys, Markdown parsing, search indices and translated error messages.

This source migration has not been browser-tested or validated end-to-end. Localized documentation is a concise guide collection; deeper engineering references in the legacy `docs/` tree remain available as source material for a future full translation.
